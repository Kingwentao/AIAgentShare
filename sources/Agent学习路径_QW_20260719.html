💡 核心认知

AI Agent = LLM（大脑） + Planning（规划能力） + Tools（执行能力） + Memory（记忆能力） + RAG（知识增强）。

INTERVIEW

面试高频题 Top 20

来自字节、腾讯、百度、快手等大厂的真题汇总

01
Agent核心

什么是AI Agent？它与传统的聊天机器人有何区别？

关键词：自主性、System Prompt + Tool + RAG、感知-决策-执行闭环。区别于Chatbot只能对话，Agent能理解目标、制定计划、调用工具、根据结果调整策略。
02
推理模式

什么是ReAct？请描述它的思考-行动-观察循环。

ReAct = Reasoning + Acting。循环：Thought（分析当前状态）→ Action（选择并调用工具）→ Observation（获取执行结果）→ 判断是否需要继续。面试时画出流程图加分。
03
工具调用

Function Calling的原理是什么？LLM如何调用外部工具？

LLM输出结构化的tool name + parameters JSON，框架层解析后执行对应函数，将结果回传LLM继续推理。本质是模型经过SFT/RLHF训练后具备的结构化输出能力。
04
协议

MCP是什么？与Function Calling有什么区别？

MCP（Model Context Protocol）是标准化工具调用协议，类比"USB接口"——让不同Agent可以即插即用地调用各种工具服务。FC是模型层面的能力，MCP是协议层面的标准。
05
RAG

RAG中长文档切片的粒度和分块策略如何设计？

考虑：固定长度vs语义切分、重叠窗口（overlap）、按段落/标题/代码块切分、父子文档结构。切片质量 > 检索算法 > 模型选择。
06
框架

LangGraph和LangChain有什么区别？为什么需要图编排？

LangChain是链式调用（线性），LangGraph引入图结构（节点+边），支持条件分支、循环、回滚、并行执行。复杂Agent任务是非线性的，需要图编排。
07
多Agent

多Agent系统有哪些通信模式？如何选择？

层级式（主控Agent分发）、辩论式（多Agent讨论达成共识）、流水线式（顺序传递）、黑板式（共享状态）。选择取决于任务复杂度、实时性要求和成本预算。
08
LLM基础

请简要介绍Transformer架构和Self-Attention机制。

Q/K/V矩阵计算注意力权重、Multi-Head Attention、位置编码、Feed-Forward层。重点理解为什么Attention能让模型捕捉长距离依赖关系。
09
Prompt

Prompt注入攻击有哪些类型？如何防护？

直接注入（覆盖System Prompt）、间接注入（通过RAG文档植入）、越狱攻击。防护：输入过滤、输出检测、权限最小化、System Prompt加固。
10
记忆

Agent的记忆系统如何设计？短期记忆和长期记忆的区别？

短期记忆=对话上下文窗口；长期记忆=向量数据库持久化存储；工作记忆=当前任务scratchpad。需考虑：记忆压缩、检索策略、遗忘机制。
11
向量数据库

FAISS、Chroma、Milvus如何选择？各有什么优缺点？

FAISS：本地高性能、无分布式；Chroma：轻量易集成、适合原型；Milvus：分布式生产级、大规模数据。选型看数据量级和部署环境。
12
RAG进阶

如何评估和优化RAG系统的检索质量？

指标：Recall@K、MRR、NDCG。优化手段：Query改写、HyDE假设性文档嵌入、混合检索（BM25+语义）、Reranker重排序、元数据过滤。
13
工程化

Agent系统上线后如何做可观测性和监控？

Trace链路追踪（LangSmith/Phoenix）、Token消耗监控、延迟分布、工具调用成功率、幻觉检测、用户满意度反馈闭环。
14
工具设计

Agent可用工具太多怎么办？如何管理工具集？

每个Agent工具不超过15个；工具分层管理；动态工具选择（根据意图加载子集）；工具描述优化（让LLM更准确选择）；工具组合与编排。
15
A2A

什么是A2A协议？与MCP有什么关系？

A2A（Agent-to-Agent）是Google提出的Agent间通信协议。MCP解决Agent与工具的通信，A2A解决Agent与Agent之间的协作通信。二者互补。
16
模型选型

不同大模型（GPT-4o、Claude、Qwen）在Agent场景中如何选型？

考虑维度：Function Calling能力、上下文长度、延迟、成本、中文能力、工具调用准确率。建议构建Benchmark评测集进行实测对比。
17
LangGraph

LangGraph中如何实现Human-in-the-loop？

使用interrupt_before/interrupt_after在中断点暂停图执行，等待人类审批后通过Command(resume=...)恢复。适用于高风险操作如发送邮件、执行转账等场景。
18
评估

如何系统评估一个Agent的性能？

维度：任务完成率、工具调用准确率、推理步骤效率、延迟P99、Token成本、用户满意度。构建评测数据集，使用LLM-as-Judge自动评估。
19
推理

Agent的三种规划模式是什么？各自的适用场景？

反应式（边做边想，适合简单任务）、规划式（先规划后执行，适合复杂任务）、混合式（规划+执行中动态调整，最灵活也最复杂）。面试必考！
20
项目实战

请讲解你做过的Agent项目，遇到的最大技术挑战是什么？

STAR法则：Situation（背景）→ Task（任务）→ Action（你做了什么）→ Result（量化结果）。重点突出"解决了什么问题"而非"用了什么框架"。

Agent = ?

Agent是一个以LLM为"大脑"的自主系统，通过 System Prompt 定义角色与行为，通过 Tools 与外部世界交互，通过 Memory 维持上下文连贯，通过 RAG 获取领域知识，具备感知、推理、规划、执行的完整能力闭环。

ReAct循环

Thought（我需要搜索天气信息）→ Action（调用weather_api("北京")）→ Observation（返回：晴，28°C）→ Thought（已获得结果，可以回复用户）→ Final Answer。这就是一个完整的ReAct循环。

MCP协议

MCP（Model Context Protocol）就像USB接口——定义了统一的工具调用标准。Agent通过MCP Client连接MCP Server，Server暴露各种工具（数据库、API、文件系统），实现"即插即用"的工具生态。

RAG流程

离线：文档 → 切片(Chunking) → Embedding向量化 → 存入向量数据库
在线：用户问题 → Query向量化 → 相似度检索Top-K → 拼接上下文 → LLM生成答案
关键优化：混合检索 + Reranker重排序

LangGraph核心

State（共享状态）+ Node（处理节点）+ Edge（连接边）+ Conditional Edge（条件路由）。支持循环、分支、并行、中断恢复，是构建复杂Agent工作流的利器。

多Agent模式

Supervisor模式：一个主控Agent分配任务给子Agent
协作模式：多个Agent平等讨论、投票决策
流水线模式：A→B→C顺序处理
选型原则：简单用单Agent，复杂任务才上多Agent
